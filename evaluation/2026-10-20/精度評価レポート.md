# 答案採点 1.2.0 精度評価（2026年10月20日）

## 結論

**現時点では、確認なしで点数・合計を確定する実務運用には不十分です。**
各欄を人が原画像と照合し、必要なら修正する「入力補助」としての試用が妥当です。
前回の24件のテスト成功は、既知の例が壊れていないことの確認であり、実用正解率の保証ではありませんでした。

今回は認識モデル・前処理・判定基準を変更せず、配布済み1.2.0を評価しました。APKは更新していません。

## 評価方法と限界

- 既存の検証画像93欄を目視し、独自に正解を記録しました。数字は0〜99の一部で、全ての数字・桁配置を網羅していません。
- 元写真は20枚。新規の93人の筆跡ではありません。以前の学習の検証用データで、元モデルの学習範囲も完全には確認できないため、未知の筆者に対する独立評価とは呼べません。
- 93欄を4〜5欄の23用紙に並べ、通常・縮小・暗さ・影・ぼけ・JPEG圧縮の6条件で計138ケースを作りました。印刷枠と手書きは実画像ですが、用紙配置・劣化は合成です。派生画像は互いに独立ではありません。
- 既存サンプル用紙の5解像度、利用者の画面画像のQR自動解読／QR位置指定を追加し、計145ケースをAndroid 15エミュレーターで実行しました。
- 学習時の自動切り出しで選ばれた画像なので、そもそも切り出せなかった入力を含む無作為な標本ではありません。
- Motorola実機のAF、手ぶれ、撮影速度、発熱、連続使用、リアルタイム確認完了までの時間は未評価です。

## 主評価：合成用紙138ケース

同じ93欄を6条件で使った558欄分の結果です。558個の独立した手書きサンプルではありません。

| 指標 | 結果 |
| --- | ---: |
| 正しく読めた欄／全欄 | 501 / 558（89.8%） |
| 誤った数字を表示した欄 | 10 / 558 |
| 未読欄（処理全体の失敗も含む） | 47 / 558 |
| 数字を表示した欄に限った正解率 | 501 / 511（98.0%） |
| 手修正なしで全欄正解の用紙 | 95 / 138（68.8%） |
| 誤った合計を確定した用紙 | 7 / 138（5.1%） |
| 合計を確定しなかった用紙 | 36 / 138（26.1%） |

誤った合計7件は、同じ2つの筆跡から作った派生画像で起きたものです。「現場の5.1%を誤る」と推定できる統計標本ではありませんが、安全上の不具合が再現することは確認できました。

「全欄正解」は合計が偶然一致しただけの用紙を含みません。

| 条件 | 正しい欄 / 93 | 誤読欄 | 未読欄 | 全欄正解 / 23用紙 | 誤った合計 |

## 見つかった重大な失敗

### 1. 「32 → 2」：6条件全てで再現

対象は `81_02`、評価用紙 `row17` の4欄目です。

- 通常画像の診断：筆跡処理は1桁の「2」（確信度約99.5%）、YOLOは2桁の「32」。最終結果は「2」。
- 縮小画像の診断：筆跡処理は「2」（約99.9%）、YOLOも文字認識も「32」。それでも最終結果は「2」。
- 正解 `[0,30,33,32]` に対し、縮小・暗さ・影・ぼけでは `[0,30,33,2]` と表示し、正しい95点ではなく65点を確定しました。

**確認できた原因**：筆跡処理が数えた桁数を基準に、桁数が違う別モデルの結果を比較対象から外してしまいます。筆跡側で桁を落とすと、正しく2桁を読んだ別モデルが拒否権を持ちません。複数の二値化で同じ筆跡を失えば、桁数の一致確認も突破します。

枠周辺の筆跡を削る前処理・境界に接した成分を除外する処理も原因候補です。どの段階で「3」を落とすかの修正・再検証は、今回の評価には含めていません。

### 2. 「31 → 1」：4条件で再現

対象は `96_04`、`row23` の2欄目。通常・暗さ・影・ぼけで発生し、そのうち3条件では合計まで誤って確定しました。こちらも十の位の欠落です。上記と同じ処理原因と断定するための個別診断は未実施です。

### 3. ライブの「2回一致」ではこの誤りを保証できない

今回の用紙評価は1回ごとの採点です。実際の連続フレームでの誤確定率は未測定です。
ただし、同じ筆跡を条件を変えても繰り返し誤るため、2回一致は正解の証拠にはなりません。実装上も同じ誤値が2回続けば確定対象になります。

## 正解データ自体の問題

既存の自動生成ラベルは、目視正解93欄のうち11欄で数値列が一致しませんでした。例えば「78」に「8」、「94」に「914」が付いています。既存ラベルで測るだけでは実際の桁落ちを見逃します。
これは今回確認した検証側の値です。学習側も同じ自動生成方式なので監査が必要ですが、全学習データの誤ラベル率を11/93と推定するものではありません。

## 実用化に向けた優先順位

1. **誤確定の防止**：別モデルがより多い桁数を検出したときは確定を止める。筆跡処理による数字消失を検出し、枠除去と筆跡保護を分離する。「32→2」「31→1」を失敗例として固定する。
2. **独立した実機評価**：後日提供予定の10〜20枚を、原画像と正しい得点の組で評価する。改善用と最終確認用を分け、同じ写真への調整だけで精度を判断しない。
3. **再学習前のラベル監査**：誤ラベルを修正し、細い鉛筆、枠に近い数字、0、100、二重線・訂正・空欄などを含む評価を追加する。
4. **運用上の目標を合意**：まず「全欄を人が照合する補助入力」で試行。提案目標は、通常撮影で手修正なし95%以上、表示した欄の正解率99.5%以上、未確認の誤合計を重点監視すること。これは提案値であり、現在の達成値や業界基準ではありません。少数画像で誤り0でも無人運用の安全性は証明できません。

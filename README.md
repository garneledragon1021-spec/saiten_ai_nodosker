# ScoreCamera Android

元の [saiten_ai_ebina](https://github.com/J2523-Sou/saiten_ai_ebina) のiPhone版をもとにした、Android向け答案採点アプリです。

## 1.5.0: 画面の自動消灯防止・確認後の解析停止

- アプリの採点画面・リアルタイムカメラを表示している間は、自動消灯を防ぎます。紙上で小問の点数を合計している間も画面を維持します。端末全体の設定は変更せず、ホームへ戻る／別アプリへ移ると通常の消灯設定に戻ります。電源ボタンによるロックを妨げるものではありません。
- リアルタイムで同じ点数を2回確認したら、結果を保持して重い再解析を停止します。**次の用紙を写したら「次の答案」を押して再開してください。** ピント・ライトを変更した場合も確認をやり直します。
- 最初の全欄読み取り後、2回目の確認までの待機を1.8秒から0.6秒に短縮します。失敗時や未読欄がある場合の待機は1.8秒のままです。認識そのものの所要時間は別にかかります。
- 筆跡成分がない中立色の欄は、従来の判定でも必ず未読になるため、余分な数字モデル・文字認識を省きます。空欄を0点にはしません。赤い筆跡の白黒再確認経路や、点数のある欄の判定基準は変更していません。
- 画面維持中は電池を消費するため、使い終わったらアプリを離れるか閉じてください。

[改善方針・比較測定・振り返り](evaluation/2026-10-26-v1.5/改善方針と振り返り.md)：自動消灯対策を確認。エミュレーターで空欄4枠の処理中央値は1,969→39ms（QR読取を除く）、記入済みサンプルは1,087→1,078msでほぼ同速度でした。実写8枚・16条件の認識結果は従来どおりで、既知の未読欄は残ります。

## 1.4.0: 暫定合計と「次の答案」

- リアルタイムカメラでは、全欄を初めて読めた時点で数字を「暫定合計（確認中）」として表示します。同じ結果を2回確認すると「合計点（確認済み）」に変わります。未読欄は0点にせず「要確認」です。
- カード下の「次の答案」で、前の点数・確認状態をクリアして次の答案に進めます。前の結果は保存しません。次の答案を写してから押してください。
- 切り替え前の処理結果は画面に反映せず、古い答案の残りの欄の処理を打ち切り、前の答案の処理後待機（1.8秒）も引き継ぎません。実行中の認識は安全な区切りまで待つため、ボタンで認識処理自体が瞬時に完了するわけではありません。
- 暫定合計は未確認なので、「閉じる」で通常の結果画面へ確定値として引き渡しません。確認済みになってから閉じてください。従来の認識モデル・精度の判定基準は変更していません。

## 1.3.0: 誤確定防止・筆跡保護・曖昧な欄の再読取

- 筆跡処理が1桁、別の認識処理が2桁と読んだ場合、短い数字を高確信という理由だけで確定しません。余分な成分が3桁を作った場合も、長い数字を無条件に優先しません。
- 赤い筆跡が十分にある欄は色で黒い枠と分離し、枠近くの線を残します。鉛筆などの中立色は検証済みの従来処理を使います。
- 未確定の欄だけ、傾き補正した枠で数字検出を再試行します。別方式の認識結果と一致し、既に検出した桁を落とさない場合に限り採用します。
- 色分離で読めない場合は従来の白黒補正も照合します。赤ペン向けの変更で、別の筆跡が読めなくなる副作用を抑えています。異なる点数の候補が残る場合は要確認です。
- 得点枠の中に完全に含まれる小さな「0」等の輪郭を、別の得点枠として数えないようにしました。
- 主となる数字モデルの重みは1.2.0から変更していません。未確定欄には、Git履歴で確認した手作業データ由来の元モデルも補助的に使用します。単独の結果で上書きせず、別方式との一致と桁数を照合します。評価画像の得点を推論コードへ埋め込んだり、画像を再学習に使ったりしていません。

画像に合わせて改善した結果は回帰評価であり、未知の写真の正解率やMotorola実機の処理速度を保証するものではありません。更新後も実際の得点と結果を照合してください。

[1.3.0の改善と比較結果](evaluation/2026-10-20-v1.3/改善内容と検証結果.md)：実写は正しい欄23→29/32、誤合計1→0/8枚。既存145ケースは誤合計7→0、誤読10→1欄に改善しました。ただし、強い圧縮では個別誤読が残り、未読欄は安全側に確定を止めています。

## スマホですぐ使う

最新版APKは[GitHub Releases](https://github.com/garneledragon1021-spec/saiten_ai_nodosker/releases)からダウンロードできます。APK本体はGitのソース履歴には含めず、リリースの添付ファイルとして配布します。

答案の実写・報告スクリーンショット・派生画像・サンプル答案画像は個人情報保護のためGitには含めていません。評価レポートは参照できますが、これらの画像を使う回帰テストには、別途ローカルの評価画像が必要です。

1. `dist/ScoreCamera-1.5.0-debug.apk` をAndroidスマホへコピーします（USB、共有ドライブなど）。旧版がある場合は上書き更新できます。
2. スマホの「ファイル」アプリでAPKを開きます。
3. 必要に応じて、そのファイルアプリの「この提供元を許可」を有効にしてインストールします。
4. 「答案採点」を起動し、用紙の得点欄数を指定します（初期値4）。写真を選ぶかカメラの使用を許可します。

Android 9以上が必要です。APKは直接インストールできる署名済みの検証用ビルドです。Google Playへの公開用ビルドではありません。

同じフォルダの `sample-answer.jpg` は3欄なので、得点欄数を3にして選ぶと、12点・95点・84点、合計191点の動作確認ができます。
採点は初回起動からオフラインで利用できます。APKにはインターネット権限がありません。

## 1.2.0: 桁落ち・撮影条件の改善とmoto g06向け調整

対象端末はMotorola PB9B0014JP（moto g06、Android 15、Helio G81 Extreme、実RAM 4GB）です。
[機種・SKU](https://store.motorola.co.jp/category/MOTOG/MOTO_G06.html)、
[メーカー仕様](https://jp-jp.support.motorola.com/app/answers/detail/a_id/192471/p/6713,16,143,343)。
現在の検証環境はAndroid 15エミュレーターであり、moto g06実機での処理速度・AF・ライトの動作確認は未実施です。

- 得点枠の四隅から枠ごとに透視補正し、内側の局所的な明るさ・影・コントラストを補正します。
- 3種類の二値化で筆跡を分離し、見えている最大桁数を2種類以上で確認します。多数決で桁を減らさず、高い確信の「2」だけを拾って「12」を「2」と確定することを防ぎます。分断された「4」など、横方向に重なる筆跡は結合して認識します。
- 約0.95MBの手書き1桁CNNを追加。公開MNISTデータから学習し、利用者画像は学習せず評価のみに使用しています。
  [モデルの由来と評価上の限界](tools/HANDWRITTEN_MODEL.md)。
- 細い鉛筆線は元の線と少し太くした線を比較し、異なる数字として強く認識される場合は要確認にします。
- YOLO・1桁CNN・文字認識を桁数と認識の確かさで比較し、空欄・不確かな欄を0点として合算しません。
- リアルタイムでは全欄が一致する結果を2回確認して合計を確定します。別の値・読取失敗・タップでの再ピント合わせ時は確認をやり直します。
- プレビューのタップでピント・露出を合わせられ、ライトを切り替えられます。1080p相当でカメラを開始できない場合は720p相当へフォールバックします。
- 4GB端末の負荷を抑えるため、モデルを共有して使い回し、推論は2スレッド、推論完了後に間隔を空けます。向き候補の画像を全て保持せず、不要画像・ライブ解析画像は解放します。

## 1.1.0の修正

- QRの四隅から傾きを求め、0・90・180・270度の候補で得点枠の並びを検証します。
- QRより下の長方形枠をOpenCVで検出し、得点欄の帯だけをプレビューします。任意の問題文の数字を得点として拾う動作を防ぎます。
- 指定した得点欄数がそろわない画像では、合計点を確定しません。現在は横並びの2欄以上に対応します。
- 数字が1個見つかっただけで高い判定基準で打ち切る処理を廃止し、ノイズ除外・異なる数字クラス間の重複除外を追加しました。
- 枠の内側だけを端末内の文字認識で補助します。認識結果が矛盾する場合や読めない場合は要確認になります。
- 読取不能は0点と区別します。結果の点数はタップして修正でき、全欄が埋まった時点で合計を再計算します。
- リアルタイム解析は1080pを要求し（対応解像度は端末依存）、失敗理由の表示と古い結果のクリアを追加しました。

低解像度・強いぼけ・影・薄い鉛筆に対する自動認識を保証するものではありません。更新後も読み取り結果と実際の得点を確認してください。

## 特徴

- リアルタイムカメラ、カメラ撮影、端末内の写真に対応
- 指定QRコード（`fujishima startup QRcode`）の確認
- OpenCVによる得点枠の検出、YOLOモデルとML Kitによる数字認識
- 設問別得点と合計点の表示
- 写真・推論結果を外部へ送信しない完全オンデバイス処理

## 動作環境

- Android 9（API 28）以上
- Android Studio Ladybug以降推奨
- JDK 17

## ビルド

1. Android Studioでこのフォルダを開きます。
2. Gradle Syncを実行します。
3. Android端末を接続し、`app`を実行します。

コマンドラインでは `gradlew.bat assembleDebug` でビルドできます。APKは `app/build/outputs/apk/debug/app-debug.apk` に出力されます。

初回ビルド時は依存ライブラリの取得にインターネット接続が必要です。インストール後の採点処理はオフラインで動作します。

## 撮影のコツ

- 答案全体と指定QRコードを画面内に入れてください。
- 紙をなるべく正面から、影や手ぶれを避けて撮影してください。
- QRコードと、その下に並ぶ得点枠をすべて画面に入れてください。
- 欄数が一致しない場合は、まず画面の得点欄数設定を確認してください。

## モデル

元リポジトリの再学習済みYOLOモデルをONNX形式へ変換し、`app/src/main/assets`に同梱しています。設問検出モデルはクラス`box`、数字認識モデルは`zero`〜`nine`の10クラスです。
